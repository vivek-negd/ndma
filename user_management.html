{

Permissions by Role

View permissions for each role

SUPER_ADMIN (Role ID: 1)

✅ view_volunteer Can view all volunteer data
✅ create_volunteer Can create new volunteers
✅ edit_volunteer Can edit volunteer records
✅ delete_volunteer Can delete volunteers
✅ create_training Can create training schedules
✅ manage_role Can create/edit roles
✅ manage_users Can manage all users
✅ view_audit_logs Can view system audit logs

YOUTH_ORG_ADMIN (Role ID: 5)

✅ view_volunteer Can view their org's volunteers
✅ create_volunteer Can create volunteers for their org
✅ view_training Can view training schedules
✅ view_deployment Can view deployments
❌ edit_volunteer Cannot edit (YOUTH_ORG_ADMIN limited)
❌ delete_volunteer Cannot delete (YOUTH_ORG_ADMIN limited)

VOLUNTEER (Role ID: 6)

✅ view_training Can view training schedules
✅ view_deployment Can view deployment info
❌ create_volunteer Limited access only
❌ manage_users No administrative access

API Command to Check Permissions

GET /api/v1/auth/profile/

Response includes: user role and effective permissions

API Commands Reference

Quick API reference for common operations

1. User Login

POST /api/v1/auth/login/

{
  "email": "user@example.com",
  "password": "password123"
}

Response: access_token, refresh_token

2. Create User

POST /api/v1/auth/create_user/

Body: { email_address, password, user_role, name, mobile }

Required: SUPER_ADMIN, NDMA_ADMIN, or TECHNICAL_ADMIN

3. Get User Profile

GET /api/v1/auth/profile/

Headers: Authorization: Bearer {token}

Response: User details + assigned roles + permissions

4. Assign Role to User

POST /api/v1/rbac/user-roles/

{
  "user_id": 5,
  "role_id": 5,
  "organization": "Red Cross"
}

Response: UserRole created

5. List All Roles

GET /api/v1/rbac/roles/

Headers: Authorization: Bearer {token}

Response: All 9 roles with permissions

6. Create Volunteer

POST /api/v1/volunteer/create/

Headers: Authorization: Bearer {token}

Body: { name, mobile, email, organization, state, district, ... }

Required Headers for All API Calls

Authorization: Bearer {your_access_token}
Content-Type: application/json

Token Validity

  • Access Token: 30 minutes
  • Refresh Token: 1 day

Help & FAQ

Frequently asked questions and troubleshooting

❓ How do I create a new user?

1. Go to Users tab
2. Fill in the form with email, name, role, etc.
3. Click Create User
4. Or use the API endpoint: POST /api/v1/auth/create_user/

❓ How do I assign a role to a user?

1. Go to Roles tab
2. Find Assign User Role section
3. Enter User ID and Role ID
4. Click Assign Role
5. Or use API: POST /api/v1/rbac/user-roles/

❓ What's the difference between role_id and user_role?

user_role: String name like "YOUTH_ORG_ADMIN" (used when creating user)
role_id: Numeric ID like 5 (used when assigning roles to users)

❓ What permissions does YOUTH_ORG_ADMIN have?

✅ view_volunteer - View their organization's volunteers
✅ create_volunteer - Create volunteers for their organization
✅ view_training - View training schedules
✅ view_deployment - View deployments

❌ Cannot edit/delete volunteers
❌ Cannot manage other users

❓ Who can create users?

Only these roles can create users:
• SUPER_ADMIN (ID: 1)
• NDMA_ADMIN (ID: 2)
• TECHNICAL_ADMIN (ID: 2)

❓ What is role hierarchy level?

Lower numbers = higher authority
• Level 0: SUPER_ADMIN (highest authority)
• Level 1-2: National admins
• Level 3-6: Regional/Org admins
• Level 7+: Regular users (lowest authority)

Higher authority can manage lower authority users.

❓ How do I get an access token?

Use the login endpoint:

POST /api/v1/auth/login/
Body: { "email": "user@example.com", "password": "pass123" }

Response: { "access": "token...", "refresh": "token..." }

❓ I forgot what role_id corresponds to which role?

Go to Dashboard tab to see the complete role hierarchy with IDs.

❓ How do I check my permissions?

Call: GET /api/v1/auth/profile/
The response will include your user role and all effective permissions.
